What this is

The full system, in one place.

Ten product pages, all built on a shared chassis we're calling V3. The CSS is canonical across the family — colors, hero hierarchy, subscribe row, ingredient tiles, supplement facts, accordion, bundle. What lives in this doc: the live pages, the design tokens, the canonical component patterns, and the copy conventions. What's still open: brand pages (About, Company, Science), the Mirror Quiz, and the SEO/AEO/GEO + metatag pass.

What's locked

The product page system is signed off. Hero hierarchy, color tokens, typography, subscribe row layout, ingredient tiles, supplement facts panel, accordion, footer — all canonical across all nine pages.

What's flexible

Per-page copy (lede, timeline labels, ingredient descriptions, accordion content) is product-specific. Photo direction is noted on each page but production photography is open. Mobile responsive behavior is in place but needs designer validation across breakpoints.

What's out of scope

Brand pages (About, Company, Science), Mirror Quiz, Blog, navigation polish, checkout. Those live in a separate workstream and will follow a similar — but not identical — design language.

--mid

--border
#E2E0DC
Card borders, dividers, separator lines, buy option borders.

Token contract

Designer should treat the seven tokens as the entire palette. No off-spec greys, no introduced blues, no alternative golds. If a UI need can't be solved with these seven, surface it as a new token request rather than improvising.

Copy & voice conventions

How the brand talks.

Editorial in tone, but grounded in research. Cormorant carries the poetry; Inter carries the proof. A few specific rules the designer should preserve verbatim, plus the do/don't pairs that show the brand's voice in motion.

Do · Product hero
"Zeta Creatine"
Use the full product name (ZETA + ingredient) in the hero banner, buy buttons, page title, structured data, and metatags. SEO/AEO/GEO depends on the literal product name appearing as a unit.
Don't · Hero
"Creatine" (alone)
Dropping the brand prefix in the hero weakens the SKU/brand pairing — both for the human reader and for downstream indexing.
Do · Body copy
"Creatine isn't just a gym thing…"
Once on the page, drop "ZETA" in the prose. The reader already knows where they are. "Creatine," "DHEA," "the formula," "this stack" all read naturally.
Don't · Body copy
"ZETA Creatine isn't just a gym thing…"
Repeating the brand in every body sentence reads like brochure copy. Save the full name for the moments where identity actually matters.
Do · Italic emphasis
"The youth hormone, replenished."
Use Cormorant italic + teal color for the one or two words you want to land. Sparingly. Usually one italic moment per headline.
Don't · Italic emphasis
"The youth hormone, replenished."
When everything is emphasized, nothing is. Italic loses its punch when used on long phrases or multiple words across the same line.
Do · Voice register
"Your cells are filling their tanks."
Plain-English metaphors. ~5th-grade reading level for body copy. Sensory if appropriate. Trust the reader to feel it.
Don't · Voice register
"Phosphocreatine saturation begins."
Save technical language for the Dig Deeper accordion. The main page reads like a person, not a label.

Open items · handoff notes

What still needs eyes.

Everything in the product page system is functionally locked. These are the items the designer should be aware of as they move into hi-fi mockups and production handoff.

Resolved
Subscribe row layout — canonical across all 9 pages
Earlier inconsistency in how the badge wrapped + the cancel-anytime text broke onto two lines. Now standardized: badge inline with "Subscribe & Save", sub stays on one nowrap line, price pinned right with flex-shrink:0. Documented in Patterns section above.
Resolved
Hero product-banner pattern — locked across the family
"ZETA [PRODUCT]" 22px teal bold, with 13px mid-grey descriptor beneath. 12px gap between, 24px margin below. Same on every page.
Action — unpin in Cowork
Two stale D+K artifacts should be removed
There are three D+K pinned artifacts: zeta-d-k-page (v1), zeta-d-k-page-v2, and zeta-d-k-page-v3-accordion (canonical). Only the v3-accordion version reflects the current system. Unpin the other two from Cowork to avoid confusion.
For designer review
Mobile responsiveness — needs validation pass
Each page has a single mobile breakpoint at ~900px. Hero collapses to single column, ingredient grids collapse to single column, supplement facts and the NOs panel stack. Designer should test all 9 pages across iPhone 13/14 widths and report any squish on the product-banner (the 22px / 0.22em tracking can feel cramped at narrow widths).
For designer review
Final photography placement
Each hero currently uses an SVG placeholder for the product canister/bottle. Photo notes (PHOTO · ZETA [PRODUCT] BOTTLE / etc.) are embedded in the markup to indicate intended placement and tone. Final imagery is the designer's call in production.
Workstream — separate
Brand pages (About, Company, Science) — not in this bundle
These follow a related but not identical design language and are being developed in a separate pass. The product page V3 system shouldn't be force-applied to brand pages without a fresh review.
Workstream — separate
SEO / AEO / GEO + metatags pass
Each page has a basic <title> and minimal head metadata. A full SEO / AEO (answer engine optimization) / GEO (generative engine optimization) and structured-data pass is pending and lives in its own brief. Designer doesn't need to action this — flagging so the metadata isn't treated as final.
Workstream — separate
Mirror Quiz, Blog, navigation polish, checkout
Not in scope for this product page handoff. Listed here for awareness.

From Cowork, export this handoff doc and the 9 product page artifacts into a single folder. Drag the folder, hit "Compress" (Mac) or "Send to → Zipped folder" (Windows), email the zip. The designer extracts and opens index.html — every link works locally with no server.
